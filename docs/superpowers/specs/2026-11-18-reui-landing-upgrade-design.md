# GESP 考级宝 ReUI Landing 升级设计

## 意图

在现有已验证首页的基础上，进行一次组件与动效升级。用户选择“尽量多放组件”，目标是更专业、更丰富、更优雅，而不是保持当前的极简组件数量。保留自然中文、真实数据、现有路由和全部业务行为。

## 已确认决定

- 从当前 `main` 新建 `redesign/reui-landing` 分支。
- 参考并采用 ReUI 的实际组件与组合方式，不只截图模仿。
- 在首页尽可能多地使用合适组件，但不加入与产品无关的图表、登录、定价或自动轮播。
- 保留“备考路径图”视觉世界、GESP 考级宝名称、Reacher 署名和现有工具页。
- 保留当前自然直接的文案风格，不恢复抽象营销术语。

## 目标

1. 让首页拥有更明确的组件层级、更丰富的可操作演示和更完整的专业工具质感。
2. 用真实组件呈现步骤、课程阶段、状态、判定、进度、FAQ 和行动。
3. 保持桌面/移动、暗色、键盘、减少动态效果和构建验证。
4. 修正首页“95 个课次”的过时文案，使用 `cppLessons.length` 的真实值。

## 非目标与反目标

- 不修改试卷分析算法、课程内容、考纲条款或 API。
- 不在首页放置无真实行为的上传框、假图表、假用户评价或虚构数据。
- 不使用自动播放轮播、持续漂浮、霓虹、玻璃堆叠或大段渐变。
- 不为了组件数量破坏阅读顺序或移动端性能。

## 考虑过的方式

### 精选 ReUI 组合

只使用 Stepper/Timeline 等少量组件，维护成本最低，但不符合用户本次明确选择的“尽量多放组件”。

### 尽量多放合适组件（已选择）

实际使用 Stepper、Timeline、Badge、Progress、Accordion、Alert、Button Group、Tabs 等，分别承担真实内容。通过统一令牌和动效约束避免堆砌感。

### 只借鉴不安装

无需新增源码和依赖，但不能获得 ReUI 已实现的组件行为与可访问性，也不满足本次参考实际组件的方向。

## 页面升级方案

### 首屏

保留互动八级路径和双行动入口，补充真实状态徽章与更精致的产品框架细节；首屏仍只保留一个主行动。

### 三项工具

将当前简单分隔列表升级为三个完整工具面板：图标、简短说明、真实能力 Badge、预览数据和明确按钮。三个入口保持同等可见。

### 使用流程

用 ReUI Stepper 替代当前静态四步区。四个步骤可点击，内容面板展示对应的真实说明与入口；完成/当前/后续状态清晰，不只靠颜色区分。

### 考纲与试卷演示

保留八级目录和分析示例，增加判定 Badge、真实进度/分值说明和 Tabs 式阅读状态；示例继续标注为演示，不冒充用户结果。

### 学习规划

用 ReUI Timeline 呈现四个课程阶段及 GESP 对应关系，展示真实 `cppLessons.length` 和每阶段 24 课次；Progress 仅用于课程覆盖估算，并保留独立作答说明。

### 依据、错误边界与 FAQ

用 Alert 呈现“非官方、估算限制、PDF 读取边界”等真实提示；FAQ 改为可键盘操作的 Accordion；保留 CCF 原文链接。

### 收尾行动

用 Button Group 组织三个真实工具入口，保持移动端正文顺序和触摸目标。

## 组件与技术约束

- 优先通过 shadcn CLI 添加 `@reui/stepper`、`@reui/timeline` 及实际需要的轻量组件。
- 安装前检查/创建 `components.json` 兼容配置，不允许初始化命令覆盖现有 `globals.css` 或品牌令牌。
- 每个添加文件都要阅读并检查依赖、导入、API 和移动端行为；移除未使用依赖与示例数据。
- 简单样式继续使用现有 Tailwind/Framer Motion；不因 ReUI 引入另一套视觉主题。
- 如某组件需要大型无关依赖或无法适应现有结构，使用现有组件实现同等行为并在交付中说明。

## 动效与可访问性

- Stepper 内容切换、Timeline 当前阶段、Accordion、Tabs、Progress、路径节点和按钮按压均有短促反馈。
- 动效以 transform/opacity 为主，支持 `prefers-reduced-motion`，不使用无限循环。
- 保持语义标题、aria 状态、键盘操作、焦点可见、移动触摸目标和无横向溢出。
- 任何自动动画不得阻塞阅读；不添加需要额外暂停控制的持续动画。

## 验证

1. 新组件在桌面、768px、390px、暗色和减少动态效果下可用。
2. 所有步骤、时间线、FAQ、工具入口、等级和演示均可操作。
3. `bun test tests`、`npm run lint`、`npm run build` 通过。
4. 完成 Unslop/Impeccable 检查、真实最终截图和独立审查。
5. 更新 `DESIGN.md`、`.impeccable/design.json` 与相关项目文档，清理临时文件并提交里程碑。

## 实施者已明确的事项

- Stepper/Timeline 的“当前/已完成”只描述访客正在查看的演示步骤，不表示真实学生进度；区域需要明确标注为演示。
- 分析示例不显示虚构得分。只说明报告如何呈现卷面分值和作答要点；没有真实试卷数据时不写分数。

## 留给实施者

- 最终组件排列可随实际渲染微调，但不能改变页面阅读顺序和产品事实。
- 具体 ReUI 组件的采用以实际依赖与源码审查为准；若跳过某个组件，需要记录原因。
- 最终中文措辞可以继续做自然度检查，不增加未证实主张。
