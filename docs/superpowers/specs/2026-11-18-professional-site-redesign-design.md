# GESP 考级宝整站重设计

## 意图

将当前直接进入考纲列表的首页改为详细、专业的 landing page，并统一重设计考纲查询、试卷分析与学习规划。新体验面向中文教育管理者、教师与家长：访客先理解产品能做什么、依据是什么，再选择适合当前任务的工具。

## 已确认决定

- 在 `redesign/professional-experience` 分支实施。
- 首页均衡介绍考纲查询、试卷分析、学习规划，由访客先了解再选择工具。
- 整站共享一套视觉系统；首页偏叙事与演示，工具页偏任务效率。
- 视觉方向采用“备考路径图”：以贯穿 GESP 一至八级的路径、阶段刻度和知识点标记连接三项真实能力。
- 采用代码驱动实现，不依赖生成图片作为页面完成的前提。
- 用户明确要求丰富动效；动效用于解释路径、状态、关联和反馈，而不是装饰性漂浮或循环背景。

## 目标

1. 首页在首屏说明产品对象、核心价值和下一步行动。
2. 用真实界面、真实考纲条款和真实课程数据展示三项能力，不虚构客户、成绩或官方背书。
3. 建立统一的导航、字体、色彩、间距、按钮、表单、卡片、状态和页尾。
4. 保留所有现有业务行为、数据、PDF 分析、报告打印与课程估算。
5. 桌面与移动端均有完整布局、键盘操作、可见焦点和减少动态效果支持。

## 非目标

- 不增加账号、付费、在线课程、成绩排行榜或社区功能。
- 不修改模型提示词、评分算法、课程覆盖算法或官方考纲内容。
- 不将产品包装成 CCF 官方产品。
- 不为了动效引入大型无关组件模板或更换技术栈。

## 反目标

- 通用 SaaS 模板式首页、空洞宣传语、无来源数字。
- 大面积高饱和色块、彩虹卡片、渐变文字、光晕和无意义漂浮。
- 动效阻塞阅读、频繁操作或打印。
- 只重做首页而保留其他页面的旧视觉语言。

## 约束与兼容

- 使用现有 Next.js 16、React 19、Tailwind CSS 4、TypeScript、Lucide 与已安装的 Framer Motion。
- 遵循 `node_modules/next/dist/docs/` 中当前版本的 App Router 约定。
- 保留中文界面、Reacher 独立作品署名、CCF 来源链接与深色/打印适配。
- `/` 成为 landing page；新增 `/syllabus` 承载原考纲浏览器。
- 原有 `/?language=cpp&level=n` 链接重定向到 `/syllabus?language=cpp&level=n`；无查询参数的 `/` 正常显示首页。
- `/analyze` 与 `/plan` 路由不变，所有跨页等级链接保留目标等级。
- 工具页继续支持打印；营销动画和导航装饰不进入打印输出。

## 考虑过的方式

### 统一整站系统（已选择）

首页与工具共享品牌和组件，按 Persuade / Operate / Read 的不同任务调整密度。优点是体验连贯、维护成本低，并能将首页的路径叙事延续到工具状态。

### 首页与工具双套视觉

分别设计营销页和工作台，表现自由度更高，但容易造成产品割裂，也需要维护两套组件与响应式规则，因此不采用。

## 视觉方向

- **世界**：课程地图、教研路径图、阶段评测标记。
- **色彩**：温和的中性背景、深墨绿正文、路径绿作为主要动作色、克制琥珀色标记当前阶段；语义色仅表示状态。
- **字体**：沿用 Geist 与中文系统字体，通过字号、行高和间距建立层级；数字使用等宽/表格数字。
- **标志性细节**：一条有起点、当前位置和下一阶段的路径线。它只出现在路径、进度、流程关联中，不变成通用装饰。
- **材质**：清晰网格、细分隔线、少量纸张层级；不使用玻璃、霓虹、彩色光晕或大量圆角胶囊。

## 页面结构

### `/`：详细 landing page

1. **首屏**：明确标题“从考纲条款到备考路径，每一步都有依据”，简短说明、一个主行动“选择你的工具”和一个次行动“了解研判依据”。右侧/下方是真实八级路径交互预览，点击等级展示该级真实主题与入口。
2. **事实条**：C++ 一至八级、CCF 原文可追溯、考纲/分析/规划三项工作流；仅使用项目已证实的数据。
3. **三项工具**：分别展示考纲查询、PDF 逐题分析、课程进度估算的真实界面摘要与明确入口，内容均衡，不强制用户优先选择某一项。
4. **研判路径**：选择等级 → 对照条款 → 分析题目 → 规划进度，以可操作步骤演示产品机制。
5. **考纲覆盖**：八级路径与各级真实单元主题，链接到对应 `/syllabus` 等级。
6. **试卷分析示例**：用真实报告结构展示题目、考点、得分要点和 CCF 条款之间的关系，明确它是界面演示而非真实用户成绩。
7. **学习规划示例**：展示课程课次、知识覆盖和通过概率估算，并保留“需结合独立作答表现”的边界说明。
8. **依据与边界**：CCF 来源、最低知识要求判定口径、估算限制、Reacher 独立作品与非官方关系。
9. **常见问题**：支持语言、PDF 类型、超纲判断、概率含义、数据来源与隐私边界；只回答代码已支持的事实。
10. **收尾行动**：再次提供三个真实工具入口与 CCF 官方来源。

### `/syllabus`：考纲查询

- 保留八级选择、条款、原文页码、题型配分与适用边界。
- 改为清晰的工具页标题、等级路径导航、可扫描的条款列表和当前等级摘要。
- 等级切换有克制的状态过渡，移动端不压缩为不可读的小表格。

### `/analyze`：试卷分析

- 保留上传、目标等级、署名、课程进度、取消、错误、分析和报告。
- 重排为明确的“文件与标准 → 分析 → 报告”工作流，提高上传区、当前对照标准和处理状态的层级。
- 分析过程按真实状态显示进度，不伪造百分比；结果出现与报告展开使用可中断的短过渡。

### `/plan`：学习规划

- 保留课程级别、课次滑块、通过概率、推荐等级、知识分析和四阶段路径。
- 将当前进度与推荐结论设为主要信息，减少大面积高饱和色块和重复徽章。
- 用连续路径替代互相孤立的装饰卡片，数字变化与课次反馈采用短促动画。

### 全局导航与页尾

- 品牌链接回 `/`；主导航为考纲查询、试卷分析、学习规划。
- 移动端提供可访问菜单，保留 CCF 官网入口。
- 页尾说明数据来源、独立作品署名与工具边界。

## 动效系统

- 首屏路径进行一次绘制与节点分层进入；之后由用户选择驱动，不无限自动播放。
- 区块进入使用一次性轻微上移与淡入，相关步骤采用 30–80ms 的小间隔。
- 路径节点、工具切换、手风琴、移动端菜单、报告状态与数字变化均有明确过渡。
- 可点击元素有 100–160ms 按压反馈；hover 只改变颜色、边框或极少量位移。
- 工具页不添加营销式滚动动效；高频操作保持即时。
- `prefers-reduced-motion` 下移除路径位移和滚动动画，保留必要颜色/透明度反馈。

## 组件与技术

- 优先扩展现有组件和 `review-styles`，避免重复实现按钮、字段和页面容器。
- 使用 Lucide 统一图标，使用 Framer Motion 处理需要中断和布局协调的交互；简单反馈使用 CSS。
- 实施前查看 shadcn registry 中 accordion、tabs、progress 等可访问组件；只有确实降低复杂度且与现有依赖兼容时才引入。
- 新增组件放在 `app/components/`，页面数据继续来自 `app/data/`，不复制考纲或课程数据。
- 不新增商业文案或未验证统计。

## 可访问性与响应式

- 语义化标题、导航、表单与按钮；所有交互可键盘完成。
- 保留跳至正文、aria-current、状态播报、错误提示和报告焦点移动。
- 路径颜色不是唯一状态信号，当前节点同时有文字/形状标记。
- 检查 390px 移动视图、768px 中间宽度和 1440px 桌面视图，无横向溢出、遮挡或过小文字。
- 打印样式保留报告与必要依据，移除营销和交互动效。

## 验证

1. `bun test tests` 通过现有考纲、版式、评分和判定回归。
2. `npm run lint` 与 `npm run build` 通过。
3. 浏览器验证首页所有入口、八级链接兼容、考纲切换、分析表单状态、规划课次交互和打印可见性。
4. 对首页及三个工具页进行桌面/移动真实截图，检查所有可达交互状态、键盘焦点和减少动态效果。
5. 完成 Unslop 检查、Impeccable polish/critique/audit 与最终设计文档记录。

## 留给实施者

- 各 section 的最终中文措辞与精确间距可在不改变产品事实和结构的情况下调整。
- 具体 shadcn 组件是否采用由现有依赖、可访问性和实现复杂度决定。
- 路径预览的内部视觉细节可根据真实数据与移动可读性调整。
- 测试可复用现有 PDF/ fixtures；若真实模型分析缺少服务端凭据，必须明确报告未验证的边界，不能伪称完成真实分析。
